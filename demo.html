In the second column, names with a dot are Reader Control API methods. Names without a dot, such as get_power, are RFID module operations sent through the method module.call.

Use Firmware APIs to inspect the API catalog advertised by the selected reader and navigate to its control. Module controls are filtered by hello.module_operations.

Every control in Reader Management Console uses the same SDK functions an application can call. Use the app to find working values, then call the function in the third column from your code.

Displayed data and counters

Reader Management Console counts every observation as it arrives. The table is a summary: it refreshes every 100 ms and shows one row per (antenna_mask, EPC, TID) with a read count. It holds at most 500 rows. When a session produces more combinations than that, the extra ones are not shown, but total reads, per-antenna reads and the unique-EPC counter still include them. Export CSV… saves only the rows in the table, so it is not a complete record of such a session.

Use SDK events or the Gateway journal when your application needs every observation. Validate DataComplete or the final data complete status before treating a session as fully delivered.

Persistence and session ownership

ControlEffect
Apply to allSets one power value on the four antennas. The value lasts until the reader is powered off.
Save to module, Save after power-offAsk the RFID module to keep the setting after power-off, for the settings that support it.
StopEnds the inventory session. The connection stays open.
DisconnectCloses the connection, so that another controller can connect to the reader.

For RF settings, check the readback before using the new value. To verify persistence, power-cycle the reader and read the setting again. An EPC write returns the module acknowledgement. Run an EPC + TID inventory, find the same TID and compare its reported EPC with the value you wrote.
