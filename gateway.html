Gateway deployment

Run the Gateway next to the readers and let a web, mobile or POS backend start scans and read tags over HTTPS.

What the Gateway does

The Gateway is one process, Ndn5030.Gateway.exe, on a PC that can reach the readers. It is the controller of every reader in its configuration. Your backend never connects to a reader directly.

PartResponsibility
GatewayKeeps the reader connection and the lease. Starts and stops scans. Stores every observation in its journal before publishing it, so that a client can read it again.
Your backendKeeps the integration token. Decides when to scan. Maps EPCs to items. Web and mobile front ends call your backend, which calls the Gateway.

The Gateway starts and stops scans. It does not change antenna power or other RF settings. Set them in TCPHost before you start the Gateway. To change them later, or to update the firmware, stop the Gateway, use TCPHost, then start the Gateway again.

Note. A reader serves one controller at a time. Select Disconnect in TCPHost before you start the Gateway. While the Gateway runs, TCPHost and SDK applications cannot connect to its readers.

Create the configuration

Run these commands in PowerShell 7 from the folder of the extracted package. They copy the template, enter your reader and create a new integration token. Replace the board ID, the reader address and the identity_file path with your own values. Keep this PowerShell window open, because the checks below read the token from it.

PowerShell 7
$cfg = Get-Content -Raw .\docs\store.example.json | ConvertFrom-Json
$id = 'ndn5030-0123456789ab'
$cfg.readers[0].board_id = $id
$cfg.readers[0].endpoint = 'wss://192.168.77.2:8443/v1/control'
$cfg.readers[0].identity_file = 'D:\station\host.json'
$cfg.integrations[0].readers = @($id)
$env:NDN_POS_TOKEN = [Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
$bytes = [Text.Encoding]::UTF8.GetBytes($env:NDN_POS_TOKEN)
$cfg.integrations[0].token_sha256 = [Convert]::ToHexString([Security.Cryptography.SHA256]::HashData($bytes))
$cfg | ConvertTo-Json -Depth 8 | Set-Content -Encoding utf8 .\store.local.json
dotnet dev-certs https --trust

The token stays in $env:NDN_POS_TOKEN for this PowerShell session. The file store.local.json receives only its SHA-256 hash. Copy the token to the secret store of your backend.

dotnet dev-certs https --trust is a command of the Microsoft .NET SDK, which must be installed on this PC. It creates and trusts a development certificate for localhost. For access from another machine, configure a certificate as described in LAN deployment below.

Then start the Gateway in a second PowerShell 7 window opened in the same folder. It keeps running in that window.

PowerShell 7
.\Ndn5030.Gateway.exe --config .\store.local.json

Configuration reference

FieldRequiredMeaning
store_idYesName of this installation. A journal database belongs to one name, so keep it unchanged.
listen_urlYesHTTPS address the Gateway listens on, with localhost or an IP address as the host. The template uses https://localhost:7443.
databaseYesPath of the journal database file, in a writable folder. One Gateway process uses one database.
journal_hoursNo. Default 24Hours that the observations and events of a finished scan stay readable. From 1 to 8760.
summary_daysNo. Default 30Days that scan summaries and idempotency keys are kept. From 1 to 3650, and longer than journal_hours.
certificate_fileNoPFX certificate served on listen_url. Without it the Gateway uses the development certificate of the machine.
certificate_password_envNoName of the environment variable that holds the PFX password.
readers[].board_idYesBoard ID that the reader reports in hello. The Gateway checks it after connecting.
readers[].endpointOne of the twoWSS address of the reader, such as wss://192.168.77.2:8443/v1/control.
readers[].serial_portOne of the twoUSB COM port of the reader, such as COM7. Use it in place of endpoint.
readers[].identity_fileYesPath of the host.json of this reader.
integrations[].idYesName of one backend. Each name is used once.
integrations[].token_sha256YesSHA-256 of the integration token, as 64 hex characters. Each integration has its own token.
integrations[].readersYesBoard IDs that this integration may use. Each must appear in readers.

Relative paths are resolved from the folder of the configuration file. The Gateway refuses to start when a required field is missing or a value is out of range.

Check the connection

PowerShell 7
$api = 'https://localhost:7443/api/v1'
$auth = @{Authorization = "Bearer $env:NDN_POS_TOKEN"}
Invoke-RestMethod "$api/readers" -Headers $auth

GET /readers lists every reader configured for this integration, including the ones that are offline. online is true when the Gateway is connected to the reader and has confirmed its board ID. When it stays false, check the reader address, the host.json file and that no other controller is connected.

LAN deployment

  1. Set listen_url to the IP address of the Gateway PC, for example https://192.168.10.20:7443.
  2. Set certificate_file to a PFX certificate whose subject alternative name contains that IP address. Put the name of the variable that holds its password in certificate_password_env.
  3. Make the backend trust the CA that issued the certificate, and call the Gateway with the same address.
  4. Allow inbound TCP connections to that port in the firewall of the Gateway PC.

Protect the database folder and the host.json files with the permissions of the account that runs the Gateway. A backend hosted in the cloud needs a private route to this local address.

Scan lifecycle for your backend

  1. Create a UUID for the user action and save it. Send POST /readers/{board_id}/scans with the UUID in Idempotency-Key. Save the scan_id from the reply. When no reply arrives, send the same request with the same UUID: the Gateway returns the scan it already created.
  2. Read tags by polling observation pages or by listening to SSE. One tag can be reported many times, each time with a new seq. Use (scan_id, seq) to skip a report you already processed. Save the cursor after you process a page or an event.
  3. Poll GET /scans/{scan_id} until stream_quality is no longer pending: the scan has then ended. After that status read, read the remaining pages. Accept the result automatically only when outcome is success and stream_quality is complete. In any other case let the operator decide or scan again.
  4. Map EPCs to items in your backend. Repeated reads of one EPC are not a quantity.

The package contains a complete polling example. It needs Node.js 22 or later and the token in the NDN_POS_TOKEN environment variable. By default Node.js does not use the Windows certificate store: save the Gateway certificate, or the CA that issued it, as a PEM file and put its path in the NODE_EXTRA_CA_CERTS environment variable before you run the example. The example scans antennas 1 and 3 for 2 seconds. Run it again with the same arguments to resume the same checkout.

Node.js 22+ · PowerShell
node .\examples\pos-checkout.mjs https://localhost:7443/api/v1 ndn5030-0123456789ab cart-42 1f0129be-bf73-41ed-b938-a516e7392b1b

A browser EventSource cannot send the Authorization header, and the integration token must not be placed in browser code. Read the SSE stream in your backend, for example with a streaming fetch, and forward the events to the browser.

Retention and replay

DataKept forAfter that
Observations and events of a finished scanjournal_hours, 24 hours by defaultReading them returns HTTP 410 cursor_expired. Read the scan summary instead.
Scan summaries and idempotency keyssummary_days, 30 days by defaultThe Gateway no longer knows the scan. Check your own records before you create a new scan.

The Gateway stores each observation before it publishes it. A page or an SSE event that you received can therefore be read again within the retention time. To resume SSE, send the id of the last event you processed in the Last-Event-ID header or in the after query parameter. The header is used when both are present. If the scan has finished and no event follows that id, the reply is HTTP 204 with an empty body.

When the Gateway stops, the reader stops RF by itself: as soon as the connection closes, or 5 seconds after the last lease renewal, and never later than max_duration_ms. After a restart the Gateway checks each unfinished scan in its journal against the reader. It never sends an interrupted Start a second time. A scan whose result it cannot confirm is reported as unknown.
