ENVI

RF configuration

Read and set antenna power, baseband profile, session, band, hopping channels and tag report filters, and write an EPC. Each operation is listed with its .NET SDK function, arguments and result. Use the same operations through WSS and USB COM.

Module transaction envelope

Every operation on this page is sent with module.call. Put the operation name in operation and its arguments in args. The reply arrives when the RFID module has answered.

A module operation needs a lease, and the reader state must be idle; otherwise the reader answers -32002 reader_not_idle. Send a new UUID in op_id and an operation name listed in hello.module_operations. The reader waits up to 3000 ms for each reply of the RFID module. After a setter is accepted, the reader reads the value back from the RFID module and compares it with your request.

The result holds op_id, state, outcome, confirmation, reason, data and steps. confirmation tells how far the operation got: none (not sent yet), transmitted (sent, no answer), acknowledged (the RFID module answered) or read_back_verified (the value read back equals the request). If the module accepted a write but the read-back failed or differs, outcome is partial. Keep the op_id and the boot_id of the reader: with them you can ask for the result again after a lost reply.

outcome · confirmation or reasonMeaning and next step
success · read_back_verifiedThe module accepted the write and the value read back equals the request. Continue.
success · acknowledgedA getter returned data, or the module acknowledged an EPC write. Continue. Verify an EPC write by scanning.
partial · readback_mismatchThe module accepted the write but reports a different value. data holds the value in effect. Use that value or correct the request.
failure · native_rejectionThe module refused the write. Check steps[].status and the argument limits.
failure or partial · tag_write_failedThe EPC write did not complete. partial means some words were written. Scan the tag by TID and decide whether to write again.
unknownThe module did not answer in time. The reader state is unknown. See Diagnostics and recovery.

These thirteen names are the complete list in hello.module_operations for firmware 0.5.0. Each SDK function returns ModuleResult. Decode<T>() returns the typed data and, like RequireSuccess(), raises ModuleOperationException unless the outcome is success. For a partial result read Data on the ModuleResult, or Result on the exception. In steps the command ID appears in decimal, for example 020B is 523.

Getters take args as {}. Setters accept exactly the listed arguments and reject any other field with -32602 invalid_or_unsupported_module_operation.

Apply and verify RF settings

  1. Stop inventory, verify idle and acquire a lease. Read get_power, get_baseband, get_rf_band, get_working_frequency and get_filter_settings.
  2. Write power, baseband and band. Use hello.power_limit_dbm as the accepted ceiling per antenna. Then set the hopping channels for the active band with set_working_frequency and the tag report filter with set_filter_settings.
  3. Require outcome=success and inspect confirmation plus data for each setter. Verify active values with the getter. Use a separate UUID for each mutation.
module.call operationargs
set_power{"power_dbm":[15,15,15,15],"persist":false}
set_baseband{"speed":3,"q_value":4,"session":0,"inventory_flag":0,"persist":false}
set_rf_band{"band_code":3}
set_working_frequency{"mode":"auto","persist":false}
set_filter_settings{"repeat_time_ms":0,"rssi_threshold":0}

The values in this table are examples. Use the band, channels and power allowed by the radio regulation where the reader is installed; the limit usually applies to radiated power, so include antenna gain and cable loss. hello.power_limit_dbm is the hardware ceiling of the reader, not a legal limit.

Send one operation at a time and wait for status.get.state to return to idle before the next one. The SDK functions wait automatically.

get_power · set_power

Read or set the transmit power of each antenna port. set_power writes the four values and reads them back.

.NET SDK: GetPowerAsync() → Decode<int[]>(). SetPowerConfigurationAsync(int[] powerDbm, bool persist = false).

ArgumentTypeDescription
power_dbminteger[4]Required. ANT1 to ANT4 in dBm. Each value from 0 to hello.power_limit_dbm.
persistbooleanOptional. true saves the values in the RFID module so they survive a power cycle. With false (default) they apply until the reader is powered off; apply them again after each power-up.
data fieldTypeDescription
datainteger[4]Power in effect, ANT1 to ANT4.

A value above the ceiling is refused with -32003 power_limited before anything is sent to the module; a value above 33 or a non-integer is refused with -32602 invalid_or_unsupported_module_operation. The SDK function checks the ceiling itself and throws ArgumentOutOfRangeException. The same ceiling applies to saved values.

get_working_frequency · set_working_frequency

Read or set how the reader hops between the channels of the active band: automatically, or over a list you choose.

.NET SDK: GetWorkingFrequencyAsync() → Decode<NationWorkingFrequency>(). SetWorkingFrequencyAsync(new NationWorkingFrequency(Mode, Channels), bool persist = false).

ArgumentTypeDescription
modestringRequired. auto or manual.
channelsinteger[]Required for manual. Up to 50 different zero-based channel indices, 0 to 49, in hopping order. Optional for auto.
persistbooleanOptional. true saves the values in the RFID module so they survive a power cycle. With false (default) they apply until the reader is powered off; apply them again after each power-up.
data fieldTypeDescription
modestringauto or manual as reported by the module.
channelsinteger[]Channel indices in hopping order.

Read the band first: an index means a different frequency in each band. On FCC, index 26 is 915.750 MHz. In manual mode the reader uses only the listed channels, in the listed order, and needs at least one. A channel index that does not exist in the active band is refused with failure and native_rejection. With the SDK pass an empty array, not null, when you send auto without channels.

get_filter_settings · set_filter_settings

Read or set the filter the RFID module applies before it reports a tag: an interval for repeated reports of the same tag and an RSSI threshold.

.NET SDK: GetFilterSettingsAsync() → Decode<NationFilterSettings>(). SetFilterSettingsAsync(int repeatTimeMs, int rssiThreshold).

ArgumentTypeDescription
repeat_time_msintegerRequired. 0 to 655350, a multiple of 10.
rssi_thresholdintegerRequired. 0 to 255, in the module's raw RSSI unit.
data fieldTypeDescription
repeat_time_msintegerRepeat interval in effect.
rssi_thresholdinteger or nullThreshold in effect. null when the module returns the repeat interval alone.

Within the repeat interval the RFID module reports the same tag only once. A tag whose RSSI is lower than the threshold is not reported. Both settings change the number of observations, so use the same filter when you compare read counts between tests.

write_epc

Write a new EPC to one tag in the field of one antenna. The tag is selected by its TID or by its current EPC. The reader computes the PC word from the EPC length.

.NET SDK: WriteEpcAsync(new NationEpcWrite(Antenna, EpcHex, TargetTidHex, TargetEpcHex, AccessPasswordHex), Guid? operationId). Keep operationId to query GetModuleResultAsync after a lost reply.

ArgumentTypeDescription
antennaintegerRequired. Port 1 to 4.
epc_hexstringRequired. New EPC, 1 to 124 hex digits. Padded on the right with zeros to whole 16-bit words.
target_tid_hexstringOne of the two selectors is required. TID prefix of the tag, 1 to 31 whole bytes, matched from bit 0.
target_epc_hexstringOne of the two selectors is required. Current EPC prefix, 1 to 15 whole words, matched from bit 32.
access_password_hexstringOptional. Exactly eight hex digits.
data fieldTypeDescription
result_codeintegerNative result of the module. 0 means the write was acknowledged.
epc_hexstringEPC as written, including padding.
word_countintegerNumber of 16-bit EPC words.
pc_hexstringPC word the reader wrote.
failed_word_addressintegerOnly on failure, when the module reports the word where the write stopped.

Select antenna 1…4 and exactly one of target_tid_hex or target_epc_hex. TID matching starts at bit 0 (1…31 bytes); EPC matching starts at bit 32 (1…15 whole words). Select a uniquely identifiable tag in that antenna's field. access_password_hex is optional and contains exactly eight hex digits.

epc_hex accepts 1…124 hex digits. Firmware pads on the right to complete 16-bit words and computes PC. For 1234AB the stored EPC is 1234AB00, word_count=2 and pc_hex=1000. Success returns acknowledged with the computed fields. Inventory EPC + TID again and verify the new EPC on the same TID.

If the reply to a write is lost, call module.result with the original op_id instead of writing again. The reader keeps the results of up to 32 setter and write operations for at least 60 seconds (hello.module_history_size, hello.module_retention_ms). They are lost when the reader reboots, and an older result can be replaced by a newer one after the 60 seconds. If the result is gone, scan the tag by TID to see which EPC it holds.

Send only the selector you use. A selector sent as null is rejected. The SDK omits unused selectors. The power cached for the chosen antenna must not exceed hello.power_limit_dbm, otherwise the reader answers -32003 power_limited.
