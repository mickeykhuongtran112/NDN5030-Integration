Test configuration

Record firmware version, board ID, boot ID, SDK version, enabled ports, power readback, baseband, band, F-hop list and upload filter before each comparison. Keep tag population, placement and antenna connections fixed. Validate one reader first, then both concurrently.

The measurements were taken over Ethernet with the 0.5.0-comport firmware image. This image differs from the standard image only in the function of the USB-C port.

Functional test sequence

  1. In TCPHost run EPC, EPC + TID and TID only on ANT1 for 5 s each. Check that the EPC and TID match the known tags and that the session reports data complete. Repeat for ANT2–ANT4.
  2. Run all four antennas, then two readers together. Confirm that counts, board IDs and sessions remain distinct and every enabled antenna produces reports with the known tag setup.
  3. Select Stop before the time limit. Wait until the reader is idle and all reports up to the final sequence number have arrived. Then start again to confirm that the next session starts normally.
  4. Close the direct connection, then run the Gateway example. Compare raw observations, unique EPCs, final quality and replayed data for the same RF configuration.
PowerShell · packaged CLI
.\Ndn5030.Cli.exe scan wss://192.168.77.2:8443/v1/control D:\station\host.json 5000 1,2,3,4 epc_tid

The CLI opens a new connection per invocation. Use it for connectivity, data completeness and report inspection. For a warm-connection latency test, keep ReaderClient connected across runs.

Latency measurement boundaries

  1. Connect once, verify idle, acquire the lease and complete RF readback. Start the event consumer before sending inventory.start.
  2. Record t0 from the UTC clock of the host immediately before StartInventoryAsync. Take t1 from ReaderEvent.ReceivedAt of the first inventory.tags event of that session; ReceivedAt is also UTC. First-tag latency is t1 − t0.
  3. For every report, record rx_mono_us (the reader's own clock, 1 ms resolution) and ReceivedAt. Compare the intervals between reports within one session. Also time each session with Stopwatch and compare it with the UTC difference, to make sure the PC clock was not adjusted during the test.
  4. Run four 5 s sessions per mode per reader, alternating EPC and EPC + TID, with both readers active in each pair. Report sample count, minimum, median, maximum and completion.
Timing definition
first_tag_ms = host_first_ReceivedAt - host_before_StartInventoryAsync
delta_i = (host_i - host_0) - (rx_mono_us_i - rx_mono_us_0) / 1000
delivery_variation_i = delta_i - min(delta_in_same_run)

The two clocks have different origins. delivery_variation measures extra delay relative to the fastest report in that run. To measure the absolute delivery time of a report, the reader clock and the PC clock would have to be synchronised, which this method does not do. Start-to-first-tag includes RF/module behavior. A tag-entry test also requires an external timestamp for physical entry. UI display timing adds the 100 ms refresh interval and the time the application needs to redraw.

Physical-reader baseline

Measured 2026-11-23 on two wired readers. Tags were already on the antennas. Each row contains four sessions; both readers ran concurrently. The 16 sessions delivered 2354/2354 observations, with zero reported drops and zero input errors.

First-tag latency is the time to the first report from any antenna. With four antennas enabled the reader reads the ports in turn, so a tag on another port can appear much later: on Reader B in EPC + TID mode the first ANT4 report arrived 1185 to 1248 ms after the first report of the session. This delay arises inside the reader, before the report is sent over Ethernet. If your application depends on how quickly a tag is seen on one particular antenna, measure that case separately. The two readers had different tag sets, so their observation counts cannot be compared.

Host software capacity

In a software-only test on the host PC, without reader hardware, the .NET SDK and TCPHost received 4080 of 4080 observations from four concurrent connections, about 510 observations per second in total. The TCPHost table stayed at its 500-row limit while the counters reached 700 unique EPCs per connection.

This test covers the PC software only. It does not measure RF performance or the Ethernet throughput of the reader. The hardware measurements above cover two readers. Before you commit to a capacity target, test with your own number of readers, tag population and session length.
