Gateway REST API

HTTPS operations to list readers, run time-limited scans and read tag data. Each operation includes its inputs, status codes, and request and response samples.

Base URL and authentication

PowerShell 7
$api = 'https://localhost:7443/api/v1'
$auth = @{Authorization = "Bearer $env:NDN_POS_TOKEN"}
$board = 'ndn5030-0123456789ab'

The backend sends its integration token as Authorization: Bearer <token> on every /api/v1 request. The Gateway checks the token and the board IDs permitted for that integration. Reader WSS and USB connections use the reader protocol described in the Control API. JSON values below are examples.

  • Download the OpenAPI 3.1.1 specification

List readers

GET/api/v1/readers

Lists the entries in store.local.json that this integration can use, including offline readers. The Gateway connects to configured endpoints. A new device on the switch appears here once it is configured and allowed for the integration. Check supports_epc_tid and supports_tid_only before requesting epc_tid or tid. Both flags are false until the first reader connection.

Parameters

This operation has no path, query or operation-specific header parameters.

Responses

Start a scan

POST/api/v1/readers/{board_id}/scans

Generate a UUID for each scan request and store it on your side before you send it in the Idempotency-Key header. If the response is lost, send the same key with the same body again: the Gateway returns the scan it already created instead of starting a second one. Keys are kept as long as scan summaries (30 days by default). Use a new key only for a new scan.

202 with a Location header for a new scan; 200 when the same key and body are sent again. 409 when the reader is busy or the key conflicts, 422 for an invalid body, 503 when the reader is offline or storage fails.

A scan uses the baseband settings (link profile, Q, session, target) currently stored in the reader; the REST API cannot change them. A reader serves one controller at a time, so stop the Gateway, set them with Reader Management Console or SetBasebandAsync, then start the Gateway again.

max_duration_ms sets the session deadline in milliseconds (1–3600000). The reader switches among the selected antennas and starts stopping RF at the deadline. Check the terminal scan result.

On the NDN5030 send all four ports in antenna_sequence, [1, 2, 3, 4]: the built-in antenna only works correctly with ANT1–ANT4 enabled together.

Request sample

PowerShell 7
$key = [guid]::NewGuid().ToString()
$headers = $auth.Clone()
$headers['Idempotency-Key'] = $key
$body = @{antenna_sequence=@(1,2,3,4); max_duration_ms=5000; data='epc_tid'} | ConvertTo-Json
$scan = Invoke-RestMethod "$api/readers/$board/scans" -Method Post -Headers $headers -ContentType 'application/json' -Body $body
$sid = $scan.scan_id

Get scan status

GET/api/v1/scans/{scan_id}

Returns the current state of one scan. Poll until stream_quality is no longer pending: only then are state, outcome and observations_persisted final. The reader can stop transmitting before the Gateway has stored the last observations; during that time state is stopping. Accept the tag list without manual review only when outcome is success and stream_quality is complete.

Stop a scan

POST/api/v1/scans/{scan_id}/stop

Stops the scan named in the URL, even if the reader has not yet started it. Calling Stop again is safe and returns the current state of the same scan. After the response, keep reading observations until stream_quality is no longer pending.

Page observations

GET/api/v1/scans/{scan_id}/observations

limit accepts 1 to 500 (default 100). Omit after for the first page, then pass the next_cursor of the previous page. The cursor is exclusive: the next page starts after it. A cursor is valid only for its own scan. Read on while has_more is true. While stream_quality is pending, new observations can still arrive after has_more was false, so poll again with the last next_cursor.

Parameters

Responses

200 · ObservationPage. 410 · cursor_expired. Polling during inventory can yield new data after has_more=false.

Request sample

PowerShell 7
$page = Invoke-RestMethod "$api/scans/$sid/observations?limit=100" -Headers $auth
if ($page.has_more) {
  $after = [uri]::EscapeDataString($page.next_cursor)
  Invoke-RestMethod "$api/scans/$sid/observations?limit=100&after=$after" -Headers $auth
}

Stream and replay events

GET/api/v1/scans/{scan_id}/events

The stream first replays the stored events of the scan, then sends new ones as they are stored. Event types are scan, observation and gap. After you have processed an event, save its id. To resume, send that id in the Last-Event-ID header or in the after query parameter; if both are present, Last-Event-ID is used. The Gateway sends a comment line every 10 seconds when there is nothing to send; ignore it. It closes the stream after the final scan event.

HTTP errors

JSON · example
{"code":"reader_busy","message":"Reader is busy."}
HTTPcodeAction
400invalid_uuidSend scan_id and Idempotency-Key as hyphenated UUIDs.
400invalid_limit / invalid_cursorUse a limit from 1 to 500 and a cursor returned for the same scan.
401unauthorizedCheck that the Authorization header carries the integration token and that the Gateway configuration holds its SHA-256.
404reader_not_found / scan_not_foundThe reader is not assigned to this integration, or the scan does not exist, belongs to another integration or has passed summary retention.
409reader_busyAnother scan is running on this reader, another controller is connected to it, or the reader is not idle. Wait and send the same request again with the same key.
409idempotency_conflictThis key was already used on this reader with a different body or by another integration. Read the original scan, or use a new key for a new scan.
410cursor_expiredThe observations and events of this scan are no longer stored (24 hours after it finished by default). Read the summary with GET /scans/{scan_id} and reconcile the transaction in your system.
415content_typeSend the body as application/json.
422invalid_scanCheck the JSON body: antenna list, max_duration_ms, a data mode the reader supports, checkout_ref length.
500gateway_errorUnexpected Gateway failure. Check the Gateway log, then retry with the same key.
503reader_offline / storage_unavailableThe Gateway has no connection to the reader or cannot write its database. Fix the cause, then retry with the same Idempotency-Key.
