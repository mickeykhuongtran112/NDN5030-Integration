Connect to a reader

Set up Ethernet WSS or USB COM control, verify the endpoint and run a time-limited scan in TCPHost.

Before you connect

  1. Extract the whole software package into one folder. The runtime is included.
  2. Power the reader with PoE or DC. Connect an antenna to ANT1 and place a Gen2 tag on it.
  3. Connect the reader to the same Ethernet network as the PC, or connect a USB-C data cable.
  4. Keep the host.json of this reader at hand. Each reader has its own file.

With no saved network profile the reader starts as a DHCP client and listens for WSS on port 8443. Look for it in the client list of the DHCP server: it announces the host name ndn5030-xxxxxx, where the six characters are the last six hexadecimal digits of its MAC address. When there is no DHCP server, or you cannot find the address, connect over USB COM first and open Connection → Ethernet configuration in TCPHost to read or set the address.

TCPHost setup over Ethernet

  1. Launch Ndn5030.Demo.exe from the extracted package.
  2. Select Add reader → Ethernet. Set Reader address to the reader IP or its full WSS URL. Select the provisioned host.json under Reader credential.
  3. Connect and check the board ID, firmware and API version, and that the header shows Connected and the RF state is idle. Repeat Add reader for each reader. To change the reader you are working with, select Readers → Open console, or use the drop-down list in the header.

host.json contains the device token and the SHA-256 fingerprint of the reader certificate. The program that connects to the reader must be able to read this file. The reader certificate is not issued by a public CA: verify it by comparing its fingerprint with the value in host.json, as TCPHost and the SDK do.

If the connection is refused, check two things. First, the credential file must be the one issued for this reader. The file does not name its reader, so keep it under a file or folder name that does. Second, a reader accepts one connection at a time. If TCPHost reports that another controller owns the reader, disconnect the Gateway, the command-line tool or the other application first.

First inventory test

  1. Place a Gen2 tag on ANT1. In RF settings, check the current power and set 15 dBm with Apply to all. Low power is enough for a tag that lies on the antenna. The value cannot exceed the board limit shown beside the control.
  2. In Read tags, select ANT1, EPC + TID, and Session limit (ms) = 5000. Select Start reading.
  3. Check that the table shows ANT1, the EPC of your tag and a rising read count. When the session ends, the status line must show RF idle, success and data complete, with the same number on both sides of the observation count, for example 120/120.
  4. Repeat with EPC only and TID only. For EPC + TID, a failed TID read can still produce an EPC observation. TID-only mode reports only successful TID observations.

IPv4 addressing and WSS

The reader gets its IPv4 address from a DHCP server or from a saved static profile. With no saved profile, the reader starts as a DHCP client and listens for WSS on port 8443. A saved profile takes precedence at boot. Use network.get to check running.dhcp, the effective address and mac.

IPv4 modeReaderDeployment
Static IPdhcp=falseSet an unused address for each reader. Use for a direct connection or an isolated switch without DHCP. On a managed LAN, coordinate static addresses with IT and keep them outside the dynamic pool.
DHCPdhcp=trueThe server supplies the address, mask and gateway. Find the reader in the client list of the DHCP server. Its address can change.
DHCP reservationdhcp=trueReserve the reader MAC on the DHCP server. Use when managed installations need stable reader endpoints with centrally maintained settings.

Example of a static setup: two readers and a PC on a switch with no DHCP server.

NodeIPv4Verification
Host192.168.77.1/24Ethernet adapter connected to the switch
Reader A192.168.77.2/24hello.board_id
Reader B192.168.77.3/24hello.board_id

On a network with a DHCP server, keep the factory setting (DHCP). Use a DHCP reservation when a reader needs a fixed address on a managed network, and a static address on a network without DHCP. To change reader mode in TCPHost, use Connection → Ethernet configuration → Save network profile, restart the reader and verify the running profile after reconnecting.

PowerShell
Test-NetConnection 192.168.77.2 -Port 8443
Test-NetConnection 192.168.77.3 -Port 8443

Two readers must not share an IP address. When you assign static addresses, connect and configure one reader at a time, and check its board ID before you save. Keep a list of board ID, MAC address and IP address for every reader.

The host opens wss://192.168.77.2:8443/v1/control. A custom client sends the provisioned device token in the Authorization: Bearer header and validates the certificate. TCPHost and the SDK use the credentials and SHA-256 certificate pin from host.json.

Address and reader credentials

FieldPurpose
Reader address or COM portSelects the connection endpoint.
host.json → tokenAuthenticates access to the reader. WSS uses a bearer header. USB COM uses an HMAC handshake.
host.json → certificate_sha256Pins the reader certificate for WSS and verifies device identity independently of the IP address.

TCPHost remembers the selected file only until you close the application; select it again after a restart. The credential belongs to the reader, not to its address: it stays valid when the IP address changes.

Keep host.json on the machine that runs the controller or the Gateway. Never put it in a web page or a mobile app. Those call your backend, and the backend calls the Gateway with its own integration token.

Multiple readers

Use a unique IP for each reader on the switch. C and D show example addresses for expansion. For USB, connect each reader through a separate USB COM port. A host can connect to reader A over WSS and reader B over COM, with one authenticated connection per reader.

  1. Add each endpoint in TCPHost and verify hello.board_id against the expected reader. For SDK integration create one ReaderClient per IP or COM port.
  2. Configure RF and start each session independently. The TCPHost reader list and selector switch the active view. Scans on other readers continue running.
  3. Each reader has its own data, its own Stop and its own connection. Check completion and the sequence numbers separately for each session.

Readers do not coordinate their RF with each other. Test readers that are installed close together for mutual interference.
