Connect to a reader

Set up Ethernet WSS or USB COM control, verify the endpoint and run a time-limited scan in TCPHost.

Before you connect

  1. Extract the whole software package into one folder. The runtime is included.
  2. Power the reader with PoE or DC. Connect an antenna to ANT1 and place a Gen2 tag on it.
  3. Connect the reader to the same Ethernet network as the PC, or connect a USB-C data cable.

Keep the PC and readers on the same LAN. The PC can use Ethernet or a Wi-Fi network bridged to the same LAN. Guest Wi-Fi isolation, VLAN boundaries or a multicast filter can prevent discovery.

  • Connect using an IP address or hostname
  • Set up an isolated switch without DHCP
  • Connect directly over USB COM

TCPHost setup over Ethernet

Search devices lists readers advertising _ndn5030._tcp.local. on the local IPv4 network. Searching leaves their controller connections free. The Readers screen shows the sessions you have opened.

  1. Launch Ndn5030.Demo.exe from the extracted package.
  2. Select Add reader → Ethernet → Search devices, select the expected board ID and click Connect reader. Alternatively, enter an IP, hostname, IP:port or a full WSS URL in Reader address. A bare address uses port 8443 and path /v1/control.
  3. Connect and check the board ID, firmware and API version, and that the header shows Connected and the RF state is idle. Repeat Add reader for each reader. To change the reader you are working with, select Readers → Open console, or use the drop-down list in the header.

Use a trusted LAN for the first connection. The reader accepts local controllers without a password or credential file. The SDK records the certificate against the board ID and checks it on reconnect.

If search returns no readers, check the active network adapter and try the known address. Found confirms an advertisement. Busy after a connection attempt means another controller owns the reader. IP conflict means different IDs advertise the same IP; give each reader a unique address.

First inventory test

  1. Place a Gen2 tag on ANT1. In RF settings, check the current power and set 15 dBm with Apply to all. Low power is enough for a tag that lies on the antenna. The value cannot exceed the board limit shown beside the control.
  2. In Read tags, select ANT1, EPC + TID, and Session limit (ms) = 5000. Select Start reading.
  3. Check that the table shows ANT1, the EPC of your tag and a rising read count. When the session ends, the status line must show RF idle, success and data complete, with the same number on both sides of the observation count, for example 120/120.
  4. Repeat with EPC only and TID only. For EPC + TID, a failed TID read can still produce an EPC observation. TID-only mode reports only successful TID observations.

USB COM control

  1. With production firmware 0.6.1, connect a USB-C data cable and find the application COM port in Windows Device Manager or the TCPHost port list. The CLI command below also lists the available ports.
  2. Select Add reader → USB-C COM, choose Application COM port, then Connect reader.
  3. Check the board ID and RF status. Run the same configuration and inventory steps as on Ethernet.
PowerShell · CLI
.\Ndn5030.Cli.exe ports
.\Ndn5030.Cli.exe status COM7
.\Ndn5030.Cli.exe scan COM7 5000 1 epc

IPv4 addressing and WSS

Each reader needs a distinct IPv4 address. All readers can listen on port 8443. A new reader using the standard Automatic profile tries DHCP and can use IPv4 link-local on an isolated switch. An existing saved Static profile survives power loss and firmware updates.

IPv4 modeReaderDeployment
Automaticdhcp=trueA router or DHCP server provides a lease. Without one, the reader checks for conflicts and selects a 169.254.x.x/16 address. Leave the PC adapter on automatic addressing on an isolated switch.
DHCP reservationdhcp=trueReserve the reader MAC on the DHCP server. Use when managed installations need stable reader endpoints with centrally maintained settings.
Static IPdhcp=falseUse a unique, unused address on the same subnet as the host when an installation requires fixed endpoints. Coordinate with the site DHCP administrator.

With an active connection, read network.get or select Connection → Ethernet configuration → Read network profile to see the effective address and MAC. A saved network profile takes effect after a restart.

  • Optional setup for an isolated switch

Moving between networks: leave Automatic (DHCP / Link-local) enabled. When changing the uplink without dropping the reader’s Ethernet link, its current DHCP lease can remain active until renewal or expiry. Search again and verify the same board ID after the address changes.

Standalone switch and optional static addresses

Connect the PC and readers to the switch, set the PC Ethernet adapter to automatic IPv4, wait for link-local addressing, then use Search devices. For installations that specifically need fixed endpoints, the following is an example static subnet.

NodeIPv4Verification
Host192.168.77.1/24Ethernet adapter connected to the switch
Reader A192.168.77.2/24hello.board_id
Reader B192.168.77.3/24hello.board_id
  1. Set the PC’s Ethernet adapter to 192.168.77.1 with subnet mask 255.255.255.0. Leave the PC gateway blank for this isolated network.
  2. For this static example, select the first reader using its application USB COM port. Verify the board ID and wait for RF idle. You can also configure a reader through its existing reachable Ethernet endpoint.
  3. In Connection → Ethernet configuration, clear Automatic (DHCP / Link-local), enter 192.168.77.2, mask 255.255.255.0, gateway 0.0.0.0 and WSS port 8443. Select Save network profile, then Maintenance → Restart reader.
  4. Reconnect reader A at 192.168.77.2 and verify its ID. Repeat for reader B using 192.168.77.3. After restart, compare the effective IP with the saved profile.
PowerShell
Test-NetConnection 192.168.77.2 -Port 8443
Test-NetConnection 192.168.77.3 -Port 8443

Reader identity and connection ownership

FieldPurpose
Reader address or COM portSelects the connection endpoint.
hello.board_idIdentifies the physical reader when DHCP or the OS changes its IP or serial port.
TLS certificate (Ethernet)The SDK compares the certificate with the SHA-256 stored for this board ID after first use.

If the certificate changes, verify the physical replacement before changing its trust record. If another board takes the same manual endpoint, search again and explicitly select its board ID.

One connection owns a reader at a time across USB and Ethernet. Disconnect the desktop app before using that reader from the SDK or Gateway. Gateway clients use a separate integration token for its HTTPS API.

Multiple readers

The PC opens a separate connection to each reader on the switch. The diagram shows four example addresses. The same topology works with DHCP leases, reservations or static addresses.

A PC can control reader A over Ethernet and reader B over USB at the same time. Identify each board at connection and keep each inventory session separate.

  1. Add each endpoint in TCPHost and verify hello.board_id against the expected reader. For SDK integration create one ReaderClient per IP or COM port.
  2. Configure RF and start each session independently. The TCPHost reader list and selector switch the active view. Scans on other readers continue running.
  3. Each reader has its own data, its own Stop and its own connection. Check completion and the sequence numbers separately for each session.

Readers do not coordinate their RF with each other. Test readers that are installed close together for mutual interference.
