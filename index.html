Choose your integration path

The NDN5030 production reader runs firmware 0.5.0 (Control API v1.4). Connect with TCPHost over Ethernet WSS or USB COM to verify the first scan, then choose an integration path below.

Set up and testTCPHost desktop appConnect a reader, set RF power and run a first scan without writing code.→.NET applicationDirect .NET SDKControl readers from a desktop application or a service with ReaderClient, over WSS or USB COM.→Web, mobile or POS backendGateway REST APIYour backend calls the Gateway over HTTPS to start scans and read tags. The Gateway keeps the data for replay.→Other languagesReader Control APIWrite your own client with JSON-RPC 2.0 over WSS or USB COM. That page shows a minimal Python client.→

What you need

ItemDetails
ReaderAn NDN5030 reader powered by PoE or DC, with an antenna on ANT1 and a Gen2 tag for the first test.
ConnectionAn Ethernet connection on the same network as the PC, or a USB-C data cable for the reader’s application COM port.
Software packageNDN5030-Demo-0.8.2-win-x64.zip for Windows x64, runtime included. It contains TCPHost (Ndn5030.Demo.exe), the command-line tool (Ndn5030.Cli.exe), the Gateway (Ndn5030.Gateway.exe) and the .NET SDK package in the sdk directory.
Reader credentialhost.json, one file per reader. It holds the device token and the certificate fingerprint of that reader. It is issued for each reader and delivered separately from the software package. Keep it on the machine that controls the reader. Contact Nextwaves if you did not receive it.
Development toolsMicrosoft .NET 10 SDK (the build tools) for the .NET path. Any HTTPS client for the Gateway path. The Gateway example in the examples directory of the package needs Node.js 22 or later.

Integration architecture

The controller sends requests and receives tag events on the same authenticated connection. Match responses using id. Use board_id, boot_id, session_id and seq to associate reports with a specific reader and inventory session.

Reader capabilities and limits

AreaNDN5030 with firmware 0.5.0
ConnectionsEthernet WSS (default port 8443) or USB COM. Each reader accepts one controller connection at a time.
AntennasFour ports. Power per port from 0 to hello.power_limit_dbm.
InventoryContinuous reading on 1 to 4 ports, limited to between 1 ms and 60 minutes per session. Data: EPC, EPC with TID, or TID.
RF settingsPower, link profile, Q, session, target, regional band, hopping channels and tag report filter.
Tag accessEPC write to one tag selected by TID or EPC.
Tag deliveryLive notifications to the connected controller. The reader does not store tags. The Gateway journal adds storage and replay.
Control ownershipLease of 5000 ms, renewed every 1000 ms. RF stops when the lease or the connection is lost.
Retry by UUID64 inventory requests and 32 module write results are kept for 60 seconds within one boot.
Message size8192 bytes per JSON message.
MaintenanceEthernet profile (DHCP or static, port), signed firmware update with automatic rollback, and restart.

Integration workflow

  1. Connect by Ethernet WSS or USB COM, verify the reader with hello and wait until status.get reports idle.
  2. Set antenna power, baseband, band and hopping configuration while RF is idle. Read back the active configuration.
  3. Start inventory for selected antennas and listen for inventory.tags. Stop the session and check the final sequence and drop count.
