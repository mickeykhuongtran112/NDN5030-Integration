Choose your integration path

With firmware 0.6.1 (Control API 1.6) and host software 0.10.0, either your application or the Gateway can hold the connection to each reader.

Ethernet WSS or USB serialDirect reader control · SDK / Control APIConnect to each reader to set RF power, band and profile, read tags or write an EPC. Use the .NET SDK in C# or send JSON-RPC requests from Python or another language.→HTTPSPOS/backend integration · Gateway REST APIKeep reader connections on the Gateway. Your backend selects a board ID, starts or stops a scan, and receives tag data by polling or through an SSE stream.→
  • Test a reader first with Reader Management Console (desktop demo)

What you need

ItemDetails
ReaderAn NDN5030 reader powered by PoE or DC, and a Gen2 tag for the first test. The antenna is built into the reading surface.
ConnectionAn Ethernet connection on the same network as the PC, or a USB-C data cable for the reader’s USB serial port.
Software packageNDN5030-Demo-0.10.0-win-x64.zip for Windows x64, runtime included. It contains Reader Management Console (Ndn5030.Demo.exe), the command-line tool (Ndn5030.Cli.exe), the Gateway (Ndn5030.Gateway.exe) and the .NET SDK package in the sdk directory.
Reader identificationSelect the board ID from Ethernet discovery or enter the address and port. For USB choose the reader’s USB serial port. Verify hello.board_id on either connection.
Development toolsMicrosoft .NET 10 SDK (the build tools) for the .NET path. Any HTTPS client for the Gateway path. The Gateway example in the examples directory of the package needs Node.js 22 or later.

Windows x64: extract the complete ZIP and launch Ndn5030.Demo.exe. For the macOS build, select the folder for your CPU (arm64 for Apple Silicon, x64 for Intel), install the matching .NET 10 Runtime and run dotnet Ndn5030.Demo.dll from that folder. Native macOS reader operation has yet to be verified.

Integration architecture

Commands and tag events share one connection per reader. Match replies by id and observations by board_id, boot_id, session_id and seq.

Reader capabilities and limits

AreaNDN5030 with firmware 0.6.1
ConnectionsEthernet WSS (default port 8443) or USB serial. Each reader accepts one controller connection at a time.
AntennasFour ports. Power per port from 0 to hello.power_limit_dbm, 30 dBm in the standard build.
InventoryContinuous reading on 1 to 4 ports, limited to between 1 ms and 60 minutes per session. Data: EPC, EPC with TID, or TID. On the NDN5030 select all four ports: the built-in antenna only works correctly with ANT1–ANT4 enabled together.
RF settingsPower, link profile, Q, session, target, regional band, hopping channels and tag report filter.
Tag accessEPC write to one tag selected by TID or EPC.
Tag deliveryLive notifications to the connected controller. The reader does not store tags. The Gateway journal adds storage and replay.
Control ownershipLease of 5000 ms, renewed every 1000 ms. RF stops when the lease or the connection is lost.
Retry by UUID64 inventory requests and 32 module write results are kept for 60 seconds within one boot.
Message size8192 bytes per JSON message.
MaintenanceAutomatic IPv4 (DHCP with link-local fallback) or static IPv4, configurable WSS port, signed firmware update and restart.

Integration workflow

  1. Connect by Ethernet WSS or USB serial, verify the reader with hello and wait until status.get reports idle.
  2. Set antenna power, baseband, band and hopping configuration while RF is idle. Read back the active configuration.
  3. Start inventory on ANT1–ANT4 and listen for inventory.tags. Stop the session and check the final sequence and drop count.
