Reader Control API

JSON-RPC 2.0 over Ethernet WSS or USB serial. Each Control API v1.6 method is listed with its .NET SDK function, parameters, result fields, errors and a request and response sample.

Transport and identification

Open wss://<reader-ip>:8443/v1/control on the trusted LAN. The reader requires no bearer header. Each WebSocket text message is one UTF-8 JSON object, up to 8192 bytes and 16 levels deep. Match replies by id and consume notifications on the same connection.

On first use the SDK associates the TLS certificate SHA-256 with hello.board_id. On subsequent connections verify that association before acquiring a lease, including after DHCP changes the address. Supply the expected board ID when the application knows it.

One controller may connect per reader. A second WSS handshake receives HTTP 503 while the slot is occupied. Disconnect the current owner before switching between Ethernet and USB.

Continue only if api_major is 1. Keep board_id and boot_id. Check capabilities and module_operations before building control requests. Wait until state is idle before taking the lease. Request fields are also specified in the downloadable JSON Schema.

JSON
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "hello",
  "params": {}
}

USB serial protocol

Open the USB serial port at 115200 8N1, with DTR asserted, RTS deasserted and flow control disabled. Each message is one UTF-8 JSON object followed by LF, up to 8192 bytes excluding LF. USB carries the same Control API as Ethernet.

Send the line below first. The reader echoes the request ID. Check result.board_id and result.boot_id before acquiring the lease. The SDK performs this exchange in ConnectAsync.

Before admission, any other valid method returns code -32001 with hello_required. If a controller already owns the reader, hello returns -32001 with reader_busy. Release the other connection before retrying.

During idle periods send status.get to keep USB active. The reader ends the USB session on DTR loss, detach or 20 seconds of host silence. To reopen, assert DTR and send hello again. The RF lease expires separately after five seconds without renewal.

JSON · request
{"jsonrpc":"2.0","id":1,"method":"hello","params":{}}

Control sequence

  1. Connect and call hello. Verify api_major, board_id and the advertised capabilities.
  2. Poll status.get until state is idle. Stop if it is unknown. After power-on or a reboot the reader reports initializing while it prepares the RFID module.
  3. Call lease.acquire. Send lease.renew about every 1000 ms with the same lease_id. The SDK renews automatically while it holds the lease.
  4. Read or apply RF settings with module.call. Wait for idle between operations.
  5. Call inventory.start with a new UUID. Consume inventory.tags and inventory.state on the same connection.
  6. Call inventory.stop or let max_duration_ms end the session. Wait for inventory.state with state finished, confirm status.get.state is idle and check that every seq from 1 to last_seq arrived.
  7. Call lease.release when finished. Close the connection to let another application connect.

Closing the connection or letting the lease expire asks the reader to stop an active inventory. After reconnecting, read status.get to check the RF state and session outcome. The reader does not replay missed tag reports.

  • Minimal client in Python that follows this sequence

Request and response conventions

ItemRule
jsonrpcAlways "2.0".
idInteger from 1 to 9007199254740991, or a string of 1 to 64 characters. The reply carries the same id.
paramsObject. Use {} when the method has no parameters.
lease_idRequired by every method that needs the lease. The reader checks the lease before it looks up the method, so a misspelled or unknown method sent without a valid lease also gets -32001 lease_required, not -32601 method_not_found.
op_idUUID in the form xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx. It names one action. The same UUID with the same arguments is a retry. The same UUID with other arguments gets -32005 idempotency_conflict. The reader returns UUIDs in lowercase.
SuccessThe reply carries the request id and a result object.
ErrorThe reply carries error with code and message. message is a stable identifier such as reader_not_idle. id is null when the request could not be read.
NotificationA message with method and params and no id. It can arrive between a request and its reply.
LimitsOne JSON object per message, up to 8192 bytes and 16 levels deep. Wait for each reply before you send the next request: the reader holds at most 4 requests it has not yet processed (lease.renew and inventory.stop use a separate queue of 4) and closes the connection when a queue is full.

The samples on this page are illustrative. Values such as board_id, boot_id, lease_id and the UUIDs are placeholders. A reader returns its own values.

lease.acquire

Gives this connection control of the reader. Every method that changes RF, network or firmware state needs the returned lease_id. Calling it again on the owning connection refreshes the same lease.

.NET SDK: ReaderClient.AcquireLeaseAsync(). The SDK stores the lease and renews it every second. Lease: not required. Reader state: idle when the reader has no owner.

Parameters: none. Send params as {}.

Result fieldTypeDescription
lease_idstringOpaque token for this ownership. Send it unchanged.
ttl_msintegerTime to live: 5000 ms from this reply.

Errors. -32001 busy if another connection owns the lease, or if a connection requests a new lease while the reader is outside idle. The current owner can refresh its existing lease even in unknown.

After power-on or system.reboot, poll status.get until state is idle before the first lease.acquire.

  "id": 6,
  "method": "lease.acquire",
  "params": {}

  "result": {
    "lease_id": "5f1c2a9e0b7d4c318e6a2f9051c3d7b4-1",
    "ttl_ms": 5000

lease.renew

Extends the lease to 5000 ms from now. Send it about every 1000 ms while the application holds control.

.NET SDK: automatic. ReaderClient renews in the background while it holds a lease. Lease: required. Reader state: any.

ParameterTypeDescription
lease_idstringRequired. Value returned by lease.acquire on this connection.
Result fieldTypeDescription
ttl_msintegerNew time to live: 5000 ms.

Errors: -32001 lease_required when the lease has expired or lease_id does not match.

After 5000 ms without renewal, the reader requests Stop for an active inventory (lease_expired), releases the lease and discards an open firmware upload. Use status.get.session to check how the session ended. The former owner no longer receives the final inventory.state.

  "jsonrpc": "2.0",
  "id": 7,
  "method": "lease.renew",
  "params": {
    "lease_id": "5f1c2a9e0b7d4c318e6a2f9051c3d7b4-1"
  }
}
JSON · response
{
  "jsonrpc": "2.0",
  "id": 7,
  "result": {
    "ttl_ms": 5000
  }
}

lease.release

Releases the lease and keeps the connection open. An active inventory receives a Stop request with reason lease_released. The reader discards an open firmware upload.

.NET SDK: ReaderClient.ReleaseLeaseAsync(). Lease: required. Reader state: any.

ParameterTypeDescription
lease_idstringRequired. Value returned by lease.acquire on this connection.

Result: the same fields as status.get, captured just before the lease is freed.

Errors: -32001 lease_required.

Stop the session with inventory.stop and wait for finished before releasing. Once the lease is released the reader has no recipient for notifications: the final inventory.state is not sent, and tag reports that arrive while RF stops are counted in reported_drops, which marks the session partial. Read the final session from status.get.session.

module.call

Runs one RFID module operation: read or change power, baseband, band, hopping channels and the tag report filter, read module identity, or write an EPC. The reply is sent when the operation has finished.

.NET SDK: ReaderClient.CallModuleAsync(operation, args, operationId) → ModuleResult, and one typed function per operation such as SetBasebandAsync. See RF configuration. Lease: required. Reader state: idle.

ParameterTypeDescription
lease_idstringRequired. Value returned by lease.acquire on this connection.
op_idstring (UUID)Required. UUID created by the application for this intent. Reuse it only to retry the same arguments.
operationstringRequired. A name listed in hello.module_operations.
argsobjectRequired. Exactly the fields of that operation. {} for getters. Up to 2048 bytes when serialized with the operation name.
Result fieldTypeDescription
op_idstring (UUID)The request UUID.
statestringfinished, or pending when a retry arrives while the transaction still runs.
outcomestringsuccess; failure (the module rejected the operation or the tag write failed); partial (the write was acknowledged, but the read-back differs or did not complete, or an EPC was written only in part); unknown (no acknowledgement, the write may or may not have been applied); pending while state is pending.
confirmationstringnone, transmitted, acknowledged or read_back_verified.
reasonstringEmpty on success. native_rejection, readback_mismatch, tag_write_failed, module_invalid_payload or a fault reason.
dataanyDecoded value for the operation. See RF configuration.
stepsobject[]Each native exchange: command (decimal command ID), status, raw_data_hex.

Each exchange with the module has a 3000 ms deadline. A setter performs a write and a read-back, so allow up to about 6 seconds. The SDK waits 12 seconds.

After the reply the reader is settling for at least 50 ms. Wait for idle before the next operation or Start, otherwise the request gets -32002 reader_not_idle. The SDK waits automatically.

Repeating a setter with the same op_id and the same args returns the stored result without sending it to the module again.

Firmware update sequence

For a production reader, select the signed application image ndn5030.bin. After reboot, hello.firmware and ota.status.running_version identify the running version. For this release both report 0.6.1.

  1. Read ota.status. With RF idle and a valid lease, send ota.begin with the signed application file size and lowercase SHA-256 hex of the entire file.
  2. Use the returned upload_id and exact byte offset for ota.chunk. Base64-encode each chunk within chunk_bytes (3072 decoded bytes). Read the acknowledged next offset. If a reply is lost, inspect ota.status before resuming.
  3. Send ota.finish to verify and stage the image, or ota.abort to discard an open upload. Inactivity for 30 seconds ends an unfinished upload.
  4. Restart with system.reboot. After reconnecting, use ota.status to compare running_version, running_elf_sha256, running_slot and boot_state with the staged result.

After booting a new image the reader confirms it once Ethernet, the control listener, USB and the RFID module have started and the reader is idle. Until then boot_state is pending_verify, and inventory.start, module.call, reader.set_config, network.set, ota.begin and system.reboot answer -32008 maintenance_busy. The same applies while an upload is open and after system.reboot has been accepted. If this does not happen within 20 seconds, the reader restarts into the previous image.

Notifications are sent to the connection that holds the lease. Tag messages wait in a queue of 32 and state messages in a separate queue of 8, so inventory.state can arrive before the last tags. When the tag queue is full the reader counts the message in reported_drops and marks the session partial. The sequence number of the dropped message is skipped, so a gap in seq shows the loss.

configuringA reader.set_config or module.call exchange is in progress.Wait for idle.
settlingA power read or module operation has just finished. The reader waits for 50 ms without module data, within 500 ms.Wait for idle.
unknownA fault. The reader cannot confirm the state of the RFID module. reason holds the cause.Read status.get to capture the fault. The lease owner can refresh its lease. New RF operations require recovery by power cycle.

Session outcome. Returned as outcome in every inventory session object.

Session outcomeMeaning
successThe session ran and stopped as requested, with no loss detected by the reader.
partialThe session ended normally but data is incomplete: a tag message was dropped or an input error occurred.
failureThe module rejected Start, reported an error at inventory end, or reported a stop before the controller requested one. A Start cancelled before execution also has this outcome.
unknownStart or Stop was not confirmed by the module.

Python Ethernet example

Use Python 3.11+ on the same LAN. Disconnect Reader Management Console from this board. The packaged example verifies the board ID and certificate, reads RF configuration and inventories ANT1–ANT4 in EPC + TID mode for 1200 ms. Replace the example address and board ID with the values from discovery.

  • Download read-tags.py

Each observation includes its sequence and available EPC/TID. The example checks the final session ID, sequence and drop counters before reporting completion.
